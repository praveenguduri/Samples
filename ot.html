🔷 Northwind Virtual Knowledge Graph

Architecture Demonstration: Ontology-Driven SQL Generation

🎯System Architecture

Key Concept: Virtual Knowledge Graph The graph stores only metadata and structure, not actual data. Real data remains in the relational database. The graph helps translate natural language queries into SQL.
1
Define Ontology
Create or import ontology (JSON-LD or TTL) defining domain concepts: Customer, Order, Product, etc.
2
Provide Database Schema
Supply JSON schema describing tables, columns, relationships from Northwind DB
3
AI-Assisted Mapping
System automatically maps tables→classes, columns→properties using RAG + ontology context
4
Build Virtual Graph (Neo4j)
Create nodes/edges representing ontology + metadata (table names, join conditions) - NO actual data
5
Natural Language Query
User asks: "Show customers who ordered products worth over $1000"
6
Graph Search → SQL Generation
Search graph for Customer→Order→Product path, extract join conditions, generate SQL
7
Execute on Relational DB
Run generated SQL on actual Northwind database, return results

💬Natural Language Query Flow

Example 1: Simple Customer Order Query

User Query: "Show me all orders placed by customer ALFKI"
1
Parse NL Query
Extract entities: Customer (ALFKI), Order
Intent: Retrieve orders for specific customer
2
Search Virtual Graph
MATCH (c:Customer)-[r:PLACED_ORDER]->(o:Order) RETURN c.sourceTable, c.pkColumn, r.joinCondition, o.sourceTable, o.propertyMap
3
Extract Metadata
Tables: Customers, Orders
Join: Customers.CustomerID = Orders.CustomerID
Filter: Customers.CustomerID = 'ALFKI'
4
Generate SQL 
SELECT 
  o.OrderID,
  o.OrderDate,
  o.RequiredDate,
  o.ShippedDate,
  o.Freight
FROM Customers c
JOIN Orders o ON c.CustomerID = o.CustomerID
WHERE c.CustomerID = 'ALFKI'
ORDER BY o.OrderDate DESC
5
Execute & Return Results
Run SQL on Northwind database → Return rows to user

Example 2: Complex Multi-Join Query

User Query: "What products did customers from Germany order in 1997?"
1
Parse NL Query
Entities: Customer (Germany), Order (1997), Product
Intent: Find products via customer→order→product path
2
Search Virtual Graph
MATCH path = (c:Customer)-[:PLACED_ORDER]->(o:Order)-[:CONTAINS]->(od:OrderDetail)-[:ORDERED_PRODUCT]->(p:Product) RETURN [node in nodes(path) | node.sourceTable] as tables, [rel in relationships(path) | rel.joinCondition] as joins
3
Extract Metadata
Path: Customer → Order → OrderDetail → Product
Tables: Customers, Orders, Order Details, Products
Joins: 3 join conditions from graph relationships
Filters: Country = 'Germany', OrderDate YEAR = 1997
4
Generate SQL 
SELECT DISTINCT
  p.ProductID,
  p.ProductName,
  p.UnitPrice,
  COUNT(DISTINCT o.OrderID) as OrderCount
FROM Customers c
JOIN Orders o ON c.CustomerID = o.CustomerID
JOIN [Order Details] od ON o.OrderID = od.OrderID
JOIN Products p ON od.ProductID = p.ProductID
WHERE c.Country = 'Germany'
  AND YEAR(o.OrderDate) = 1997
GROUP BY p.ProductID, p.ProductName, p.UnitPrice
ORDER BY OrderCount DESC

Example 3: Aggregation Query

User Query: "Which employees processed the most orders?"
1
Search Virtual Graph
MATCH (e:Employee)<-[r:PROCESSED_BY]-(o:Order) RETURN e.sourceTable, e.propertyMap, r.joinCondition
2
Generate SQL with Aggregation 
SELECT 
  e.EmployeeID,
  e.FirstName,
  e.LastName,
  e.Title,
  COUNT(o.OrderID) as TotalOrders
FROM Employees e
LEFT JOIN Orders o ON e.EmployeeID = o.EmployeeID
GROUP BY e.EmployeeID, e.FirstName, e.LastName, e.Title
ORDER BY TotalOrders DESC
